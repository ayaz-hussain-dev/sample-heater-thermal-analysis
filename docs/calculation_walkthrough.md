# Calculation and code walkthrough

This note explains how the results are obtained from the supplied evidence. The CAD and FEA were carried out in CATIA/ANSYS. Python reads their exported histories; it does not replace or rerun the finite-element solver.

## 1. Solid volume and mass

For block length L, width W, height H, n wells, well diameter D and depth d:

```text
V = L W H - n pi D² d / 4
m = density V
C = m cp
```

Use SI units in thermal calculations: 1 mm³ = 1e-9 m³. The resulting values are:

| Quantity | A | B |
|---|---:|---:|
| Solid volume | 44380.885 mm³ | 32380.885 mm³ |
| Mass | 0.122935052 kg | 0.089695052 kg |
| Heat capacity C | 107.568171 J/K | 78.483171 J/K |

The identical wells cancel in the mass difference. The removed slice is 60 × 40 × 5 mm³, or 33.24 g. Relative to A's solid mass, that is 27.039%.

## 2. Convecting area

The heater base has no convection in this model. The removed top-face disks and the well floors have equal areas. The remaining area simplifies to:

```text
A_conv = L W + 2 H (L + W) + n pi D d
```

This gives 0.008209557 m² for A and 0.007209557 m² for B. This expression includes the bore walls and their floors, consistently with the ANSYS convection scope.

## 3. One-state heat balance

Energy stored equals heater input minus convective loss:

```text
C dT/dt = P - h A_conv (T - T_ambient)
UA = h A_conv
tau = C / UA
T(t) = T_ambient + (T_initial - T_ambient) exp(-t/tau)
       + (P/UA) [1 - exp(-t/tau)]
```

The analytical predictions at 600 s are 66.752756 °C and 80.772426 °C. These sit inside the corresponding whole-body FEA ranges. The calculation shares the same assumed power and losses; it is a consistency check, not a comparison with a physical experiment.

The initial conductivity interpolates to 148.62 W/(m·K). With characteristic length V/A_conv, Bi = h (V/A_conv) / k is about 0.000364 for A and 0.000302 for B. This supports an approximately uniform bulk temperature. A base heater still produces local gradients, which this one-state model cannot resolve.

The stored-energy and loss columns in results/lumped_check.csv belong to this analytical model only. They are not an independent energy-balance export from the FEA.

## 4. Time to a temperature benchmark

The wall minimum is used so the benchmark has been reached across the selected cylindrical wall scope. If the target lies between two exported samples, linear interpolation gives:

```text
t_target = t_0 + (T_target - T_0)/(T_1 - T_0) × (t_1 - t_0)
```

For A, the 60 °C crossing is between 491.25 and 492.5 s. The script obtains 491.966 s. For B it obtains 349.741 s. Therefore:

```text
time saved = 491.966 - 349.741 = 142.225 s
percentage reduction = (1 - 349.741/491.966) × 100 = 28.910%
```

Times displayed in the report are rounded estimates. Exported temperatures are reported to about 0.001 °C, and physical boundary-condition uncertainty is much larger than that numerical display resolution.

## 5. Temperature spread at a fair comparison point

At each design's own 60 °C minimum-wall crossing, interpolate its maximum-wall value at that same time:

```text
spread = maximum wall temperature - minimum wall temperature
```

A gives 0.177280 °C and B 0.227207 °C. B heats faster but has a larger spatial wall range at matched temperature. Comparing only their maximum whole-body temperatures at 600 s would hide that distinction.

## 6. Numerical comparisons

For each controlled coarse/fine pair, scripts/analyse.py compares the finer history at the coarser history's times. It computes the largest absolute difference over the entire history, as well as the final difference. Mesh and time-step comparisons are kept separate.

The largest body-Tmax differences are 0.001 °C for the tested mesh pairs, then 0.034, 0.017 and 0.014 °C for the time-step pairs. The corresponding body-Tmin checks are also provided. The 600 s peak heat flux changes by about 13-17% with mesh refinement, so it is not treated as a converged design limit.

## 7. File processing

1. Read each supplied tab-separated table and retain its raw bytes in data/raw.
2. Verify row count, sequential row IDs, finite values, temperature bounds and the fixed time grid.
3. Retain the original exported timestamp column. Reconstruct the documented fixed clock as row ID × time step to avoid GUI rounding of 0.625 s timestamps.
4. Write per-case CSV files and summary tables.
5. Calculate threshold crossings, spatial ranges, parameter sensitivities and the analytical comparison.
6. Generate separate Python figures. Original CAD/ANSYS images are never regenerated by these scripts.

The tests cover an adiabatic heating limit, exponential cooling over one time constant, the independently calculated removed mass/area, threshold interpolation and all 18 export clocks.

## What to explain when discussing the project

- Why reducing solid mass improves warm-up under fixed heater power.
- Why a faster response can still have a larger local temperature range.
- Why one numerical parameter is changed per comparison, and why a local flux peak needs a different accuracy claim from a smooth temperature field.
- What an empty-holder model leaves out when predicting actual fluid-sample temperature.
